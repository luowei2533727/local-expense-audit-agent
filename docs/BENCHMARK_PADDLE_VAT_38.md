# 中国增值税发票基准测试

本报告只统计 PaddleOCR 数据集中的 38 张中国发票。两套数据合计 88 张，整体规模和三模型合并结果见[综合评测报告](BENCHMARK_SUMMARY.md)。

## 数据与口径

数据来自 PaddleOCR 增值税发票关键信息抽取数据集，共 38 张有结构化标注的中文发票（train 30 / val 8）。归档 SHA-256 为 `b65bf3b6639758fe98c2c076fbc5b527006a66f01616c2fbe4d36ab06a1a1a1f`。仓库不分发原始图片。

官方标注覆盖价税合计、税额、开票日期、发票号码和购买方名称，不包含销售方名称及发票代码。未标注字段不纳入准确率。

## Agent 结果

38 条真实发票字段按固定顺序构造原始基线、缺少票据、高额报销、未来日期和多重风险五类场景。每个模型运行全部 38 条，共 114 次调用。标准答案由生产接口使用的确定性规则函数生成，结果为规则一致性评测，不代表欺诈识别准确率。

| 模型 | 结构化成功 | 完整决策准确率 | 检查覆盖率 | 检查状态准确率 | 平均耗时 | P95耗时 | 平均TTFT | Token/s | 修复率 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| `qwen3:4b-instruct` | 38/38 | **100.0%** | 93.1% | 93.1% | **36.52s** | **44.15s** | 5.03s | 10.29 | **0.0%** |
| `phi4-mini:3.8b` | 37/38 | 92.1% | 84.5% | 83.6% | 48.06s | 67.08s | **3.01s** | **11.58** | 100.0%（成功样本） |
| `qwen3.5:4b` | 38/38 | 81.6% | **100.0%** | **96.4%** | 72.32s | 71.23s | 17.54s | 9.68 | 2.6% |

完整决策要求建议、风险等级和缺失材料同时正确。检查覆盖率单独统计模型是否完整返回全部依据，因此总体决策正确并不代表检查明细完整。

`qwen3:4b-instruct` 在质量、稳定性和延迟之间表现最好，被选为默认文本审核模型。`qwen3.5:4b` 保留为视觉模型，因为文本审核和图片字段提取属于两个独立环节。

## OCR 结果

视觉模型固定为 `qwen3.5:4b`，温度为 0，输入图像自动旋转并缩放至最长边 1536 像素，单张超时 300 秒。38 张全部完成，完整运行（含 114 次 Agent 调用）耗时约 3 小时 32 分钟。

| 指标 | 结果 |
|---|---:|
| 结构化成功 | 38/38（100.0%） |
| 价税合计严格准确率 | 97.4%（n=38） |
| 税额严格准确率 | 97.4%（n=38） |
| 开票日期严格准确率 | 100.0%（n=37） |
| 发票号码严格准确率 | 97.4%（n=38） |
| 购买方名称严格准确率 | 97.4%（n=38） |
| 购买方名称平均字符相似度 | 99.8% |
| 标注文本平均召回率 | 87.6% |
| 平均延迟 / P95 延迟 | 178.05 秒 / 208.50 秒 |

模型能够输出销售方名称及发票代码，但由于上游缺少对应标签，这两个字段不纳入正式准确率。

`qwen3.5:4b` 的 Agent 平均延迟高于 P95，是因为 `b138` 单条请求耗时 634.93 秒；其余最高请求耗时 71.23 秒。报告保留该异常值，不对平均值做截尾处理。

## 运行时约束

模型只能调用白名单只读规则工具。服务端在结果入库前再次核对建议、风险等级、缺失材料和检查明细；发现遗漏或风险降级时，以确定性规则补齐并降低置信度。所有结果仍要求人工审批，模型不能直接修改报销状态或执行付款。
