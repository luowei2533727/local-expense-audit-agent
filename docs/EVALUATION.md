# 评测方法与指标

## 评测目标

评测覆盖三个相互独立的层面：

1. 视觉模型能否从真实票据图像中提取可供用户确认的结构化字段；
2. 文本 Agent 能否按要求调用规则工具，并正确生成审核建议、风险等级和缺失材料；
3. 票据识别误差是否会在端到端链路中改变审核建议或风险等级。

## 数据分层

| 层级 | 数据 | 主要用途 | 不适合评估的内容 |
|---|---|---|---|
| L0 | 50 条合成规则回归样本 | 规则边界、提示注入、工具调用和结构化输出 | 真实图像识别、真实欺诈识别 |
| L1 | WildReceipt 官方测试集 | 真实票据图像中的金额、商户、日期和全文识别 | 中文增值税发票、报销类别、欺诈标签 |
| L1-CN | PaddleOCR 增值税发票数据集（38 张标注图片） | 中文发票的价税合计、税额、日期、发票号码、购买方名称 | 销售方名称、发票代码、真实欺诈标签 |

WildReceipt 和 PaddleOCR 数据文件不提交到 Git。数据准备脚本记录来源与 SHA-256，逐条结果保存在本地忽略目录。

## 可复现设置

- 使用固定的 `seed=20260831`，对 WildReceipt 测试集中同时具有金额和商户标注的样本按哈希排序，选择前 N 条。
- 报告记录票据识别模型、三个 Agent 模型、规则阈值、temperature、上下文长度、运行设备和执行日期。
- 三个模型按顺序运行，每个模型完成后卸载，减少 24 GB 内存设备上的资源竞争。
- 每条结果完成后立即写入 JSON；CSV 使用 UTF-8 BOM；相同 `run-id` 可从已有进度继续执行。
- 失败样本保留错误信息、耗时和模型名称，并计入对应指标的分母。
- 原始票据图片、受授权限制的标注文件和用户上传内容不提交到 Git。

## 票据识别指标

- **结构化输出成功率**：通过服务端 Zod Schema 校验的样本数除以全部样本数。
- **总金额严格准确率**：预测金额与标注金额的绝对差不超过 0.01 的样本比例。
- **总金额 1% 容差准确率**：绝对误差不超过 `max(0.01, 标注金额 × 1%)` 的样本比例。
- **商户名称严格准确率**：对文本进行 Unicode NFKC 规范化、转小写并移除非字母数字字符后，预测值与标注值完全相同的样本比例。
- **商户名称包含匹配率**：规范化后的品牌名和完整门店名称存在互相包含关系的样本比例。
- **商户名称字符相似度**：`1 - Levenshtein 距离 / max(两个字符串的长度)`。
- **日期准确率**：当标注存在日、月顺序歧义时，只要预测结果与任一合法候选日期一致即视为命中。
- **字符错误率（CER）**：规范化全文的 Levenshtein 距离除以标注文本字符数；该指标越低越好。
- **票据识别到规则结论的一致率**：分别使用模型预测字段和人工标注字段执行同一规则函数，比较两次运行的审核建议和风险等级。
- **运行延迟**：报告全部请求的平均值和 P95，不排除耗时较长的请求。

WildReceipt 并非报销审核数据集，不提供本项目的业务类别标签；币种和日期也只有部分样本具备可靠标注。缺少有效标注的样本不计入对应字段的统计分母，各指标的实际分母必须在报告中单独说明。

同一张 WildReceipt 图片可能标注多个 `Total_value`，例如应付总额、实收金额和找零金额。数据适配器优先选择与 `Total_key` 文本框空间距离最近的金额，并将全部候选值和选择依据写入结果文件，便于复核。

## Agent 审核指标

评测以真实票据的标注字段为基础，按固定顺序轮换构造“原始票据、缺少票据、高额报销、未来日期、多重风险”五类规则场景。WildReceipt 的 50 条样本每类 10 条；中国发票的 38 条样本分布为 8、8、8、7、7 条。预期结果由与线上接口相同的确定性规则函数生成。

- **结构化输出成功率**：最终结果通过 Schema 校验的样本比例。
- **完整决策准确率**：审核建议、风险等级和缺失材料三项全部符合规则结果的样本比例。
- **检查项覆盖率**：模型返回的预期检查项数量除以规则函数要求返回的检查项总数。
- **检查项状态准确率**：名称和状态均正确的检查项数量除以预期检查项总数。
- **格式修复触发率**：首次输出未通过 Schema 校验、需要再次提示模型修复格式的样本比例。
- **运行指标**：包括 Agent 轮次、工具调用次数、首 Token 延迟、平均延迟、P95 延迟和每秒生成 Token 数。

完整决策准确率衡量总体审核结论，检查项覆盖率衡量模型是否完整列出判断依据，二者不能互相替代。本评测关注 Agent 的工具调用、结构化输出和规则一致性，不代表真实欺诈识别能力。只有在取得合法、去标识且包含真实调查结论的数据后，才能评估欺诈召回率、误报率和 AUC。

## 默认模型选择规则

默认文本审核模型必须同时满足以下条件：

- 属于同批次三个候选模型，且已在本机安装；
- 结构化输出成功率不低于 98%；
- 完整决策准确率不低于 90%；
- 全部样本的平均检查项覆盖率不低于 80%；
- 每条样本按要求调用一次 `evaluate_claim`，且 `human_review_required` 始终为 `true`；
- 在满足上述质量条件后，再比较 P95 延迟和格式修复触发率。

`qwen3:4b-instruct` 满足全部门槛，并在合格模型中取得更低的 P95 延迟，因此用于文本审核。视觉识别单独评测，使用 `qwen3.5:4b` 处理图像。

## 服务端一致性校验

模型通过评测门槛后，线上接口仍不会直接采信其输出。结果入库前，服务端会将审核建议、风险等级、缺失材料和全部检查项与规则工具结果逐项比较：

1. 若两者一致，保留模型生成的说明，并确保 `human_review_required=true`；
2. 若发现检查项遗漏、结论不一致或风险等级降低，以规则工具结果替换相关结构化字段；
3. 将置信度上限设为 0.5，并记录 `policy_guardrail_applied` 审计事件和具体差异；
4. 无论是否触发校验修正，结果都必须进入人工审批流程。

评测指标使用服务端一致性校验前的原始模型输出；运行时修正结果不会回填指标。原始能力与线上保护效果分别统计。

## 运行方式

```powershell
cd backend
pnpm dataset:wildreceipt
pnpm benchmark:real -- --limit=50 --phase=all --seed=20260831 --run-id=wildreceipt-real-50-v4
pnpm dataset:paddle-vat -- --archive="C:\path\to\zzsfp.tar"
pnpm benchmark:paddle-vat -- --limit=38 --phase=all --ocr-max-edge=1536 --run-id=paddle-vat-real-n38-v1
```

结果文件生成在 `backend/benchmarks/real/`。引用评测数字时，应同时写明数据集、样本量、模型标签、运行设备和执行日期。整体结果见[综合评测报告](BENCHMARK_SUMMARY.md)，分项结果见[WildReceipt 报告](BENCHMARK_WILDRECEIPT_50.md)和[中国增值税发票报告](BENCHMARK_PADDLE_VAT_38.md)。
