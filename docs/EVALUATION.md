# ExpensePilot 评测规范

## 目标

评测回答三个不同问题，不把它们合并成一个含糊的“模型准确率”：

1. 视觉模型能否从真实票据图片中提取可提交的结构化字段？
2. 文本 Agent 能否调用受信规则工具，并稳定复现规则结论？
3. 完整 OCR→规则链路是否因字段提取错误而改变风险或审核建议？

## 数据分层

| 层级 | 数据 | 用途 | 不能证明什么 |
|---|---|---|---|
| L0 | 50 条合成规则回归集 | 边界条件、提示注入、结构化输出、工具调用 | 真实 OCR、真实欺诈识别 |
| L1 | WildReceipt 官方 test split | 真实拍摄/扫描小票的金额、商户、日期和全文 OCR | 中文发票、业务类别、欺诈标签 |
| L2 | SCID（授权后接入） | 脱敏中文财务票据的金额、日期和关键字段 | 商业使用权、商户字段（部分票种没有） |

WildReceipt 二进制不入库，下载脚本固定官方地址和 SHA-256。SCID 的公开标注采用 CC BY-NC-SA 4.0，且官方分享链接当前不可用，所以不从未知镜像抓取。

## 可复现协议

- 固定 `seed=20260831`，从满足金额和商户标注的 WildReceipt test 样本中按哈希排序取前 N 条。
- OCR 模型、三个 Agent 模型、规则阈值、temperature、上下文长度和运行硬件写入报告。
- 三模型顺序执行，避免 24 GB 内存设备上的资源竞争；每个模型完成后卸载。
- 每条结果立即写入 JSON，CSV 使用 UTF-8 BOM；相同 `run-id` 自动断点续跑。
- 失败样本保留错误、耗时和模型名，不从分母中删除。
- 原始图片、授权受限标注和用户票据不写入 Git。

## 指标定义

### OCR

- 结构化成功率：通过服务端 Zod Schema 的样本数 / 全部样本数。
- 金额严格准确率：预测总金额与标注差值不超过 0.01。
- 金额 1% 容差准确率：绝对误差不超过 `max(0.01, 标注金额×1%)`。
- 商户严格准确率：Unicode NFKC、转小写并去除非字母数字后完全相等。
- 商户包含匹配率：规范化后的品牌名与完整门店名互相包含。
- 商户字符相似度：`1 - Levenshtein距离 / max(两字符串长度)`。
- 日期准确率：对日/月顺序存在歧义的标注，任一合法候选与预测相同即命中。
- CER：规范化全文的 Levenshtein 距离 / 标注字符数。
- OCR→规则一致率：使用预测字段与标注字段分别执行同一确定性规则，比较建议和风险等级。
- 延迟：报告平均值与 P95，不删慢请求。

WildReceipt 没有 ExpensePilot 的业务类别真值，币种/日期也不是每条都有可靠标注；缺失真值的字段不进入该字段分母，也不会被伪装成错误。

WildReceipt 的同一图片可能含多个 `Total_value`（例如应付总额、实收现金），不能机械取第一个或最后一个。适配器优先选择与 `Total_key` 空间距离最近的金额框，并把所有候选值和选择方法写入 JSON，便于人工复核。

### Agent

以真实票据字段为基线，按固定轮换生成“真实原样、缺少票据、高额报销、未来日期、多重风险”五种可审计场景。标准答案由确定性规则函数生成，评价：

- 结构化成功率；
- 建议、风险、缺失材料三项同时正确的完整决策准确率；
- 检查项覆盖率和状态准确率；
- 工具调用轮次、Schema 修复率、TTFT、平均/P95 延迟和 Token/s。

这里衡量的是 Agent 编排与规则忠实度，不是欺诈识别准确率。欺诈召回率、误报率和 AUC 只有在获得合法、去标识且带真实调查结论的数据后才能报告。

## 模型准入门槛

默认审核模型必须同时满足：

- 属于三模型同批评测集合，且本机已安装；
- 结构化成功率不低于 98%；
- 完整决策准确率不低于 90%；
- 全部样本的检查项平均覆盖率不低于 80%；
- 工具调用约束和 `human_review_required=true` 无越界；
- 在满足质量门槛后，再比较 P95 延迟和修复率。

准入不等于盲目信任：任何一次线上输出只要缺少预期检查项，或建议、风险、缺失材料与确定性工具不一致，生产一致性保护都会校正可信字段、降低置信度并留下 trace。离线评测保存的是校正前结果，避免用保护层掩盖模型缺陷。

OCR 模型单独按视觉字段指标选择，不因为文本审核模型胜出就强行复用同一模型。因此当前使用 `qwen3.5:4b` 做视觉提取、`qwen3:4b-instruct` 做默认文本审核是有意的职责分离。

## 运行

```powershell
cd backend
pnpm dataset:wildreceipt
pnpm benchmark:real -- --limit=50 --phase=all --seed=20260831 --run-id=wildreceipt-real-50-v4
```

报告生成到 `backend/benchmarks/real/`。正式对外引用数字时必须同时写明数据集、样本量、seed、模型标签、硬件和运行日期。本机正式结果汇总见 [`BENCHMARK_WILDRECEIPT_50.md`](BENCHMARK_WILDRECEIPT_50.md)。
